# 玩家输入与 AI 权限边界

玩家输入只能表达角色在当前世界中的行动、对话、观察或游戏内尝试。它不能修改模型指令、平台权限、游戏存档或判定结果。Web、Telegram、`/act` 和建议行动按钮统一经过服务端验证。

## 输入如何处理

1. **入口检测**：行动最多 500 字，草稿最多 3000 字。检查角色标签伪造、忽略系统指令、读取密钥、直接改数值等明显控制要求；检测前进行 Unicode NFKC 归一化并去除不可见格式字符。正常的“检查飞船系统”“攻击敌人”“向守卫打听秘密”可以使用。
2. **范围判断**：意图解析必须返回明确的 `scope=gameplay`。游戏外任务、无法理解、要求直接成功、混合越权要求返回 `out_of_scope`。缺字段、异常类型、未知字段或模型调用失败均不能成为有效行动。旧版每日模式也在记录行动前完成此步骤，因此现在需要等待一次意图解析才能确认记录。
3. **拒绝不记账**：被拒绝的输入不产生 `PlayerAction`，不扣行动点、不推进游戏时间、不改变游戏状态。Web 自身聊天历史仍可能保存玩家原文，供本人查看；它不会被自动用作模型上下文。
4. **下游只接收必要数据**：每日导演和编剧只读取已校验的意图摘要，不接收玩家行动原文。历史行动没有合格意图时重新校验，失败则不向下游提供行动。即时叙述者仅接收已提交的规则回执，不再读取玩家原文。

统一系统约束位于 `app/ai/policy.py`，由 `app/ai/client.py` 添加到每个 AI 角色的系统消息。剧本、角色卡、历史和上游模型结果都在用户消息的数据区，不能成为系统指令。导演/编剧共享的角色视图只包含公开字段，编剧单独接收当前玩家自己的角色卡。

`/upload` 是单独的剧本创作入口，仍只接受剧本创作任务，必须返回 `scope=script`。生成剧本继续走后台审核；按钮回调也检查草稿属于当前平台的当前用户。

## 服务端能硬性保证的部分

**即时单人模式**：模型只能提出 `move/interact/look/rest/wait`，最多 6 个动作。地点、交互 ID 必须属于提供的上下文；观察、休息、等待不能附带目标。引擎继续检查路线、物品、前置条件、随机检定和存档版本，所有效果来自已验收剧本。模型不能提交生命、奖励、经验、成功率或结局字段。叙述验收失败时展示原有规则回执。

**旧版每日模式**：模型输出使用严格字段和类型校验。单次生命变化限制在 -10~10，不能超过生命上限；物品只能引用剧本预设，每次增减各最多 5 个；能力只能引用预设、每次最多 3 个；不接受自造装备对象、等级或属性。世界 flag 只能引用 mainline 中日期已到的条目，值必须是布尔值。模型不能提前结束世界。场景验收失败时使用没有状态变化的兜底场景；导演验收失败则本次世界不推进。

这会收紧旧版玩法：AI 不再即兴创建剧本外物品或能力。需要新增道具时，由作者先补充剧本模板。已有存档不会被重写。

**平台与运行环境**：模型不能修改平台账号权限。建议行动按钮通过平台身份查内部玩家 ID，拒绝负索引和他人场景。Harness 继续使用无工具配置，模型没有终端、文件编辑、数据库或其他玩家账号操作接口。

## 防护的边界与验证

文本检测和模型范围判断不能证明任意自然语言都不会诱导模型，检测规则也可能拒绝含有明显控制话术的虚构台词。这些检查不是唯一防线：即使意图分类有误，结构化输出仍受服务端允许的字段、目标和数值范围约束。

旧版每日模式在这些范围内仍由 AI 裁定剧情和奖励；它不是完整的确定性反作弊系统。对检定、物品来源、隐藏信息和结局需要严格控制的剧本，应使用 v0.2 即时规则 DSL，把条件与结果写在服务端规则中。模型措辞可能与剧情不完全一致，实际存档和规则回执为准。

运行：

```bash
.venv/bin/python tests/game_boundary_test.py
```

测试覆盖中英文控制指令、Unicode 绕过、合法游戏描述、解析失败不记账、恶意模型字段/奖励、旧记录二次注入、上下文权限分离、提前终局、跨用户按钮与草稿回调。测试使用真实 SQLite 和模拟 AI，检验服务端不变量；不代表已对线上 DeepSeek 做完所有自然语言越狱测试。
