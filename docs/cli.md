# 命令行模式

在已安装项目依赖的 Python 环境中，从项目根目录启动：

```bash
python run_cli.py
```

Linux 本项目虚拟环境也可以直接运行：

```bash
.venv/bin/python run_cli.py --profile 青岚散修
```

入口自动建表并添加尚未存在的内置剧本，不覆盖已有剧本和存档，也不创建后台管理员。无需先运行 `seed.py`，无需启动 Web、Telegram、MySQL 或 Redis。

## 交互

第一次启动会显示单人剧本列表，输入编号创建世界。之后直接描述角色的行动，回复以小说正文为主。需要选项时输入 `/guide`，再输入展示的编号；执行后不自动刷新菜单，旧编号也不会悄悄对应另一个动作。编号对应当前界面上的选项，不是剧本 ID。

例如选择「长生录 · 凡尘修仙」后：

```text
你 > 修炼
你在蒲团上盘膝坐定，依着功法缓缓吐纳。一缕微凉的气息随着呼吸入体……
...
你 > 地图
...
你 > 去青岚谷
...
你 > 采药
...
你 > /quit
```

| 命令 | 功能 |
| --- | --- |
| `/scripts`、`/create_world` | 浏览并创建单人世界 |
| `/status` | 查看角色、物品和当前进度 |
| `/resume` | 恢复最近的存档，重读上次结果 |
| `/guide`、`/options` | 主动展开当前游戏玩法与可执行选项 |
| `/log` | 最近经历 |
| `/continue` | 主动等待5分钟；不能越过叙事流介入点 |
| `/pause`、`/stream on` | 暂停或恢复主动叙事 |
| `/pass` | 明确选择暂不介入当前事件，让世界继续 |
| `/autonomy` | 查看三种自主性；可用 `world=95 player=30 narrative=85` 修改 |
| `/act 行动描述` | 明确提交一次行动，也可直接输入文字 |
| `/settle` | 手动结算旧版每日单人世界的一天 |
| `/help`、`/start` | 命令行使用说明 |
| `/quit`、`/exit` | 退出 |

在输入提示处按 Ctrl+C 或发送 EOF 同样会退出。每次动作即时保存，无需额外的保存命令。在处理行动时强行中断进程，重新启动后应先核对存档；已经提交的动作仍然存在，不会自动重放。

## 本地档案

`--profile` 默认为 `default`，允许1-32个可显示字符。同一数据库、同一档案名会恢复同一玩家，启动时自动显示最近的进行中或已结束旅程。

```bash
python run_cli.py --profile 青岚散修
python run_cli.py --profile 灯塔看守人
```

档案名经过 Unicode NFKC 规范化并去除两端空白，映射成稳定的平台身份。存档仍保存在配置的 SQLite 数据库中，默认 `data/storyworld.db`，路径以项目根目录为准。运行时请位于项目根目录，以读取该目录下的 `.env`。

本地档案是本机的存档选择功能，不是密码账号。`cli`、`web` 和 `telegram` 身份相互独立；同名不会关联其他渠道的角色。此版本提供单人终端游玩，多人房间仍使用 Web 或 Telegram。

## AI 与结算

修仙模式的编号动作和基础指令（修炼、采药、交易等）不依赖 AI，可离线游玩，使用本地小说式描写。配置 AI 时，通过已有 DeepSeek Harness 结合最近经历润色正文，不附数值回执；润色失败时保留本地描写，不重放动作。更自由的表达与交流仍需 AI 理解。

修仙世界拥有独立叙事时钟，等待键盘输入期间也会输出世界事件；每段默认约18秒，介入点自动暂停。事件不替玩家修炼、消费或加入阵营。不带叙事流定义的旧即时剧本仍只在行动时推进，均不需要 `/settle`。旧版每日单人剧本先记录行动，再用 `/settle` 调用原有每日结算引擎，立即在当前终端显示结果。每天可手动结算一次，结算成功后进入下一游戏天，再次输入会结算下一天；不受真实日期限制。此过程需要可用的 AI 服务，失败时保留原进度以便重试。

CLI 自带独立叙事循环，输入由独立线程读取；退出后停止主动叙事。它不启动旧版每日调度器，不向 Telegram 或其他终端发送消息。若另外运行 `start_all.py` 并共用数据库，其已有每日调度仍会扫描运行中的旧版世界；终端重新查看 `/resume` 或 `/log` 可以读取已保存结果。

## 验证

```bash
python tests/cli_test.py
```

测试使用临时 SQLite 文件，覆盖真实终端入口、标准输入、退出与重启恢复、独立档案、菜单编号、旧版每日结算、只读操作和异常处理，不修改玩家真实存档。

## 直接试玩小说切片

`python run_cli.py --demo` 直接呈现雨幕便利店正文，使用独立 `novel-demo` 档案。无需操作，每30秒继续一段，二十段后在介入点停住。随时自由输入；新一轮用 `--profile 新档案名`。固定节奏不受 `/autonomy narrative=...` 改速（0仍暂停），也不循环重播。详见 [体验规格](novel-vertical-slice.md)。

## AI 故障排查

执行 `python run_cli.py --check-ai` 检查配置位置、密钥是否已配置和 Harness 是否可加载（不联网、不输出密钥）。缺少配置时退出码为2。启动时会提示同一问题，仍允许阅读作者正文及使用离线动作。项目 `.env` 按项目根目录读取，不受启动目录影响；环境变量优先。

CLI 的 AI 故障写入 `data/logs/cli-ai.log`，按大小轮转。日志只含固定错误码、后端名和异常类型，不含玩家输入、密钥及 SDK 原始诊断。`missing_api_key` 是未配置密钥，`harness_setup` 是环境未就绪，`invalid_ai_response` 是响应验收失败；这些情况不再伪装成“请说清想做什么”。
