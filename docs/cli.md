# 命令行模式

在已安装项目依赖的 Python 环境中，从项目根目录启动：

```bash
python run_cli.py
```

Linux 本项目虚拟环境也可以直接运行：

```bash
.venv/bin/python run_cli.py --profile 青岚散修
```

入口自动建表并添加尚未存在的内置剧本，不覆盖已有剧本和存档，也不创建后台管理员。无需先运行 `seed.py`，无需启动 Web、Telegram、MySQL 或 Redis。

## 交互

第一次启动会显示单人剧本列表，输入编号创建世界。之后直接描述角色的行动，回复以小说正文与本次变化为主。需要选项时输入 `/guide`，再输入展示的编号；执行后不自动刷新菜单，旧编号也不会悄悄对应另一个动作。编号对应当前界面上的选项，不是剧本 ID。

例如选择「长生录 · 凡尘修仙」后：

```text
你 > 修炼
你收束杂念，沿周天吐纳。修为 +10，目前 10/30。
...
你 > 地图
...
你 > 去青岚谷
...
你 > 采药
...
你 > /quit
```

| 命令 | 功能 |
| --- | --- |
| `/scripts`、`/create_world` | 浏览并创建单人世界 |
| `/status` | 查看角色、物品和当前进度 |
| `/resume` | 恢复最近的存档，重读上次结果 |
| `/guide`、`/options` | 主动展开当前游戏玩法与可执行选项 |
| `/log` | 最近经历 |
| `/continue` | 即时剧本等待5分钟 |
| `/act 行动描述` | 明确提交一次行动，也可直接输入文字 |
| `/settle` | 手动结算旧版每日单人世界的一天 |
| `/help`、`/start` | 命令行使用说明 |
| `/quit`、`/exit` | 退出 |

在输入提示处按 Ctrl+C 或发送 EOF 同样会退出。每次动作即时保存，无需额外的保存命令。在处理行动时强行中断进程，重新启动后应先核对存档；已经提交的动作仍然存在，不会自动重放。

## 本地档案

`--profile` 默认为 `default`，允许1-32个可显示字符。同一数据库、同一档案名会恢复同一玩家，启动时自动显示最近的进行中或已结束旅程。

```bash
python run_cli.py --profile 青岚散修
python run_cli.py --profile 灯塔看守人
```

档案名经过 Unicode NFKC 规范化并去除两端空白，映射成稳定的平台身份。存档仍保存在配置的 SQLite 数据库中，默认 `data/storyworld.db`，路径以项目根目录为准。运行时请位于项目根目录，以读取该目录下的 `.env`。

本地档案是本机的存档选择功能，不是密码账号。`cli`、`web` 和 `telegram` 身份相互独立；同名不会关联其他渠道的角色。此版本提供单人终端游玩，多人房间仍使用 Web 或 Telegram。

## AI 与结算

修仙模式的编号动作和基础指令（修炼、采药、交易等）不依赖 AI，可离线游玩，使用本地小说式描写。配置 AI 时，通过已有 DeepSeek Harness 结合最近经历润色正文，简短显示本次实际变化；润色失败时保留本地描写，不重放动作。更自由的表达与交流仍需 AI 理解。

即时剧本的时间只在行动时推进，不需要 `/settle`。旧版每日单人剧本先记录行动，再用 `/settle` 调用原有每日结算引擎，立即在当前终端显示结果。每天可手动结算一次，结算成功后进入下一游戏天，再次输入会结算下一天；不受真实日期限制。此过程需要可用的 AI 服务，失败时保留原进度以便重试。

CLI 本身不启动后台每日调度器，不向 Telegram 或其他终端发送消息。若另外运行 `start_all.py` 并共用数据库，其已有每日调度仍会扫描运行中的旧版世界；终端重新查看 `/resume` 或 `/log` 可以读取已保存结果。
