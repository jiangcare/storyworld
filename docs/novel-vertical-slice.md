这不是一个等待玩家提问并回答的 AI 聊天游戏。它是一部由游戏世界持续驱动、由 AI 实时写作、玩家可以随时介入并改变走向的可游玩小说。

1. 故事默认自己前进，而不是默认等待玩家。
2. 玩家默认自由输入，而不是默认做选择题。
3. 游戏机制默认隐藏在小说下面，而不是用系统语言打断小说。

# 十分钟可游玩小说：体验验收规格

本轮只回答两件事：不操作能否读下去；中途自由介入能否改变事实与后续小说。新增平台功能暂停。旧修仙、多人、装备与渠道留在仓库，但不作为本轮进度指标。

## 最小范围与启动

一个世界、一间便利店及门前同一视野、三个 NPC（王强、许青、老赵）；没有商城或成长系统。屋檐、店内、车后是同场景内的站位，不扩展地图。预设二十段世界事件，每段推进一分钟，约每30秒投递一段。无输入路线由十八点四十走到十九点；玩家主动行动另计其耗时。

在项目虚拟环境运行：

```bash
python run_cli.py --demo
# 新一轮实验使用不同档案，不覆盖旧存档
python run_cli.py --demo --profile 雨夜第二次
```

默认使用独立 `novel-demo` 档案。再次启动恢复同一段落；不自动重置进度。开场直接正文，无剧本列表。`/pause`、`/stream on` 是阅读控制；`/status` 显式查看库存。CLI 等待输入期间时钟继续运行。已有 Web/Telegram 可从剧本列表进入同一 Demo，不新增渠道。

作者正文允许离线连续阅读。自由表达通过已有 DeepSeek Harness 意图解析和叙述接口处理；少数明确别名可离线执行。不是承诺任何一句话都能产生世界效果，未知动作应简短澄清且保持世界状态，不能把它冒充成成功。

## 不输入的十分钟

| 现实阅读时间（约） | 世界事实与叙述任务 | 不能发生 |
| --- | --- | --- |
| 0:00 | 屋檐开场，三人各有具体动作 | 强迫玩家进入房间、展示选项 |
| 0:30–3:00 | 蜡烛、电线、药盒、街角声音；人物关系由动作呈现 | 重复介绍房间，要求回复才能继续 |
| 3:30–5:00 | 挪货架、拆窗钉，七个人影逐渐可见 | 写“事件触发”“恐惧值增加18” |
| 5:30–7:30 | 遮光、卡轮、拉布带，危险逼近 | 自动替玩家堵门、花费物资或决定救人 |
| 8:00–9:30 | 第一次撞击、窗缝、退路的迹象 | 提前替玩家逃跑或强制失败 |
| 10:00 | 门将失守；车后路线则有影子靠近藏身处，自然停笔 | 补“你准备怎么办”、强行继续伤害玩家、重放第一段 |

LLM 润色与传输会增加等待，十分钟是作者事件的目标节奏，不是网络计时 SLA。无输入路线二十段不重复；最后介入点与已投递正文落库。离线不积累突发消息。

## 中途自由介入的实验

在第四段前后，直接输入：

> 我不进去，我躲到对面的车后面观察。

验收：角色站位变成车后，仍在同一场景；NPC 没有擅自知道玩家藏身处。下一段沿原来的事件时序，写车后能看到的动作；听不清的小声对白不能原样出现。结尾危险从玻璃门改为绕向车头的影子。不是换几个形容词，投递回执必须记录选择了隐藏分支。

另开一次实验输入：

> 我先把门堵死，问他们这里有没有后门。

验收：解析为玩家明确授权的堵门与询问。货架被木楔固定，NPC 王强从抵门转去协助修窗；后续不能继续写歪轮滑走或整架倒塌。老赵只透露当前已有的后窗事实，不替玩家承诺同行。未知表达不能任意映射到最有利的行动。

输入“拿水和饼干”：仅在角色已进入店内时执行；库存恰好增加三瓶水、两包饼干，重复执行不再次发放。正文写拿取与收纳，不出现奖励列表。`/status` 才显示库存。观察、聊天、错误意图不消费行动资源。

复杂新行为（如拆车制造声源）尚无规则，不得声称已经完整模拟。优先用这类实际试玩反馈决定下一项必要的交互，禁止借机扩展一套装备或制作平台。

## 错误与正确输出

后台事实：七个影子靠近；王强恐惧增加18；世界时间经过两分钟。

**拒收：**

> 事件触发：丧尸群到达。王强恐惧值增加18。时间经过2分钟。请问你要怎么办？

**可接受：**

> 第一个人影从招牌下面转了出来。随后是第二个，第三个。它们走得很慢，肩膀却始终朝着亮着烛光的玻璃门。
>
> “七个……”王强数到最后，声音突然轻下去。他后退半步，脚跟碰到了货架的铁脚。

后台事实：库存水+3、饼干+2。

**拒收：** `【系统】获得矿泉水×3，压缩饼干×2。`

**可接受：**

> 你拉开最下面的纸箱，里面还剩三瓶没有拆封的水和两包压缩饼干。纸箱底已经受潮，提起来时软了一下。你把它们收入背包，拧紧了瓶盖。

## 提问边界

- 普通段落结束、场景变化、获得物品、NPC 情绪变化、计时推进后，绝对不追加助手提问。
- 关键介入点也不补“请选择”。让门、手、视线与沉默承载暂停。
- 允许已成立场景内的 NPC 对白提问，如“还能修吗？”。这不是每次提问都暂停的理由。
- 玩家明确问玩法或打开系统界面可以说明；意图无法定位对象时允许一次短澄清。这些例外不能变成每轮固定收尾。
- 不得替玩家决定“拼死保护她”、加入阵营、消费重要资源。玩家只说观察时，不能自动搜索和拿走物资。

## 验证证据与未完成验收

自动测试使用真实临时 SQLite 与可控时钟，覆盖600秒无输入、二十次独立事件、最终暂停和不重放、分支 NPC 状态、库存事务、重启与未知意图。已有 stream 测试覆盖真实 Web、CLI 读入和投递失败。测试推进600秒逻辑时钟，不冒充真人连续阅读十分钟。

**真人体验：待验证。** 测试不能证明“好看”。试玩时记录：在哪一段想关掉、重复或因果断裂的位置、插话有没有被接住、有没有被替做决定、是否看过菜单才知道如何继续。任一体验失败都优先修核心叙事，不用新增功能冲抵。验收通过后才重新评估更大世界的开发范围。
