# 本地 SQLite 部署

游戏存档、账号、聊天记录、后台/Web 登录会话、上传草稿及每日结算租约统一保存在 SQLite 中。安装 Python 依赖后即可运行，不需要 MySQL、Redis 或 Docker。

## 配置和启动

`.env` 只需填写 AI 密钥。数据库默认为：

```dotenv
DATABASE_URL=sqlite:///data/storyworld.db
```

相对路径按项目根目录解析，切换启动目录不会另建一份存档。也可设置绝对地址，如 Linux 的 `sqlite:////home/me/storyworld.db` 或 Windows 的 `sqlite:///C:/StoryWorld/data/storyworld.db`。程序自动创建父目录和表结构。请把文件放在本机磁盘上。

```bash
python seed.py
python start_all.py
```

仅玩即时单人副本时可单独运行 `python run_web.py`；旧版每日剧情需要 `start_all.py` 或 Bot 调度器运行。

## 持久化与并发

- 外键开启，写入等待上限 10 秒，WAL 允许读操作与写入并行。
- 即时行动在 AI 解析完成后执行 `BEGIN IMMEDIATE`，重新读取并验证版本，然后一次提交；AI 生成叙述期间不持有写锁。
- 旧版行动点直接统计已保存的行动记录，限额检查和新行动在同一个写事务中完成，重启不会恢复已花费的行动点。
- 会话和草稿写入 `runtime_entries`，保留原有有效期；每次写入清理过期条目，读取时也检查过期时间。重启后未过期会话仍有效，退出登录会删除会话。
- 每日结算使用带随机持有者标识的 600 秒租约。只有当前持有者能提交或释放锁；过期旧任务不能删除新任务的锁。所有 AI 场景先生成，最后以短写事务提交。租约失效或输入状态改变时放弃结果，等待下一次调度。
- Web、Bot 和后台可以分别运行并共享同一数据库。WebSocket 在线连接仍属于各 Web 进程的内存，因此 Web 服务建议使用单 worker；数据库跨进程互斥不等于跨进程实时消息广播。

SQLite 适合本机单人和少量用户。它同一时间只有一个写事务，当前实现通过缩短写事务减少冲突，暂未针对大规模并发部署设计。

## 备份与恢复

```bash
python backup_db.py backups/storyworld-2026-09-07.db
```

使用标准库 SQLite 在线备份接口，包含 WAL 中已提交的数据；目标文件必须不存在。不要在程序运行时仅复制主 `.db` 文件并遗漏 WAL。

恢复时停止 Web、Bot、后台，选择备份的新路径作为 `DATABASE_URL` 后重启即可。原数据库文件保留，方便回退。数据库包含账号、会话与私有剧情，`data/` 和 SQLite 文件已加入版本库忽略规则。

## 原有部署

之前的 `MYSQL_*` / `REDIS_*` 配置不再使用，安装依赖已移除对应驱动与服务。此改动不会连接、删除或清空旧数据库，也不会自动把旧 MySQL 存档复制到新库。已有正式存档需要在切换前单独迁移；新安装直接使用 SQLite 即可。Redis 中的旧登录会话与临时草稿也不会自动迁入。

## 验证

所有测试均使用真实临时 SQLite 文件，无需外部服务。`tests/local_storage_test.py` 覆盖会话重读/失效、跨进程争抢租约、并发行动限额、过期计划拒绝、结算期间的其他写入、嵌套 JSON 持久化和租约过期保护；其余玩法与 Web/后台回归继续运行。
