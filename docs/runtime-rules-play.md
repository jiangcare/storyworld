# 动态功法与试法：本轮实现

本轮实现了 [运行时规则补全](runtime-rule-evolution.md) 的最小闭环：可信来源 → 冻结候选档位 → AI 提出功法参数 → 验收 → 规则与灵力初始化、研习效果原子提交 → 按固定规则试法。不是完整战斗系统，也没有让模型执行代码。

## 直接游玩

进入「长生录 · 凡尘修仙」，在洞府输入：

```text
功法
研习引露诀
吐纳蓄灵
用引露诀在火纹试法石试法
灵力
我的功法
试法规则
```

首次研习需要真实 AI；也支持“我把洞府那册引露诀摊开，试着研读其中护身的行气法门”等自由表达，由意图层选择对应来源。具体强度、消耗与反射等由模型在预算内补全，不是预写功法效果。

已有已验收功法后，明确的研习/吐纳/试法指令可离线执行，不重新生成规则。一次处理一段研习、吐纳或试法；复合意图先停在执行前，避免新功法尚未理解就接续施放。

内置来源为洞府的《引露诀》（水属护持）、《照烬诀》（火属冲击），以及达到炼气二层后可主动感悟的“轮回印异象”。异象的五行属性与冲击/护持类型在首次推演前由引擎抽取，失败重试复用票据，不改变复活规则。其他自定义剧本需在 `narrative.runtime_rules` 中声明来源、吐纳地点与试法石；原样内置修仙存档可直接使用，无须改写旧剧本 JSON。

已出现等待玩家介入的变故时，修习先暂停。可先回应眼前局势，或明确 `/pass` 表达不介入；学习功法不能替玩家解决剧情选择。

## 运行环境

正常部署使用兼容系统的 Python 3.11 与 `requirements-harness.txt`，配置项目 `.env` 后运行 `python run_cli.py`。首次启动自动建两张新表，保留旧存档。

当前这台旧宿主机的 Python 3.9 无法运行官方 Harness。已在 `.infra/` 准备隔离 Python 3.11.16 和官方 SDK，借用本机已有 `node:16` 镜像中的 glibc 2.28，提供本机兼容入口：

```bash
./run_cli_compatible.sh --check-ai
./run_cli_compatible.sh --profile default
```

相同 profile 使用原来的 SQLite 存档。入口只运行 CLI，不启动 Web、Telegram 或后台服务，不把密钥放进进程参数。容器退出后删除；Python/依赖缓存留在 Git 忽略的 `.infra`。脚本依赖本机已经准备的缓存，不是通用安装器；新环境优先按正常部署方式安装。

## 已固定的法则

- 规则执行内核版本为1，只支持五行/无属的单次冲击或护持。每段交锋依次验证资格、同时承诺代价、处理属性关系、计算影响、结算一次反射；不允许自定义优先级、公式、脚本或触发链。
- 功法强度1–20、消耗1–10、穿透0–8、反射0–50%。冲击不能反射，护持不能穿透。效果预算 `power + 2*penetration + ceil(reflection/10)` 不超过来源档位的 `8*tier`，也不超过 `cost*3`。这些是内核验收条件，模型不能覆盖。
- 水克火、火克金、金克木、木克土、土克水；被克一侧本次有效强度降至原来的四分之三，向下取整且至少为1。没有“元素正确就绝对获胜”。
- 穿透削减部分护持强度；反射只作用于被挡下的冲击，反射本身不再次触发反射。双方都是护持时无伤害，不进入无限触发。
- 首次研习时创建独立灵力池，当前值为0；容量为 `min(100, 10 + 2*min(初始rank,45))`。这是本阶段初始化规则，不兑换生命、修为或物品。后续学习、重启和复活不重置池子；本阶段容量不随突破自动升级。损坏或不兼容的池记录拒绝执行，不擅自修正或补满。
- 已掌握功法后，在声明的吐纳地点每15分钟凝聚最多3灵力，不能超过容量；池满则不消耗时间。研习新功法需要15分钟，重读不重复扣时；试法需要1分钟及功法规定的灵力。

试法石是受控演练，石上能力及规则快照在玩家研习时就固定。每次试法内部提供独立的对照灵力，不代表真实 NPC 获得无限资源。碰撞结果留在 `last_trial` 和行动回执中；隔绝阵保护玩家，没有生命伤害、战利品或经验收益。真实 NPC 对战、持续状态、空间交换等新构件仍未实现，不能冒充支持。

## 保存与一致性

`rule_drafts` 按世界和来源唯一，保存来源哈希、抽取结果与预算；候选票据不表示能力已激活，失败时可以保留以防重抽。

`runtime_rules` 保存已验收规则的不可变版本、正文参数哈希、候选来源和激活修订号。第一版只激活版本1，不提供原地修改、自动升级或删除接口。世界保存基础规则快照，角色引用确切规则版本。来源或对照规则被修改时拒绝继续执行，不在战斗中静默替换。

模型网络等待不占写事务。回来后重新核对世界修订号、角色状态、来源、地点、资格及规则预算；规则注册、灵力初始化和行动回执在同一次 SQLite 提交中完成。竞争提交只成功一次；提交失败不留下激活规则或半个灵力池。

即时行动支持可选请求 ID，来自真实消息 ID 的 Telegram 文本自动使用；同一世界、玩家及请求 ID 重放已保存结果，内容冲突拒绝执行。不带请求 ID 的新输入仍视为新尝试，不能承诺没有稳定消息标识的通道可自动识别网络重发。已学功法本身按来源去重，无论有无请求 ID 都不重新发放。

## 验证

```bash
python tests/runtime_rules_test.py
# 显式启用后会调用已配置的真实 DeepSeek；只用临时数据库，不连接聊天渠道。
STORYWORLD_TEST_RULES_LIVE=1 python tests/runtime_rules_live.py
```

离线测试覆盖来源预算、非法规则、权限、灵力初始化、反射/穿透对称性、候选重试、并发、事务回滚、世界隔离、状态漂移、重启和消息重放。真实 Harness + `deepseek-v4-flash` 已跑通过自由输入研习、规则生成、蓄灵、试法、小说正文及重放；使用临时存档，无生产世界写入。

真人长时间阅读与更多能力组合的平衡仍需试玩；这一闭环不代表任意超能力或无限世界规则都已可生成。
