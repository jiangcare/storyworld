# v0.2 第一轮：即时单人游戏闭环

本轮对应设计第 3、6、8、10、21 节，优先让玩家自由行动产生可持久化的真实后果。

## 试玩

配置 `.env` 中的 `DEEPSEEK_API_KEY`；数据库默认使用本地 SQLite，无需额外服务，然后执行：

```bash
.venv/bin/python seed.py
.venv/bin/python run_web.py
```

打开 `http://127.0.0.1:8081/web`，注册昵称，选择「钟楼雨夜 · 即时单人体验」。创建后立即出现开场，无需等待每日推送。

可以输入「我假装受伤，引林舟靠近，再偷他的钥匙」或「我去档案室调查水情记录，再拿上救援绳」。也可以描述自己的其他计划；当前动作范围无法表达的意图会说明未执行，不会编造成功结果。

- 自由输入：AI 拆成至多 6 个有顺序的动作；检定失败、无效步骤或新关键节点会停止后续动作。
- `/continue`：观察五分钟并触发符合条件的背景事件。关键节点等待自由行动，不代替玩家做决定。
- `/status`：查看位置、时间、生命、背包、线索、关系、经验与等级。
- `/resume`：加载最近旅程的结构化状态和最后一次结果，已结束的旅程也能重读结局。
- 每回合自动保存，不依赖浏览器聊天记录。Web 底部也提供对应入口。

副本有合作救援、独自逃生和洪水死亡三种结局。偷钥匙成功率由敏捷公式计算，当前主角为 70%；失败会受伤并降低关系。救援必须持有并消耗绳索。关键抉择出现后，普通等待和休息暂停，玩家仍可移动、调查和执行自己的计划。

## 规则与存档

剧本通过 `content_json.narrative` 显式启用新运行时；现有单人/多人剧本继续使用原有每日结算。新运行时不会进入旧的 AI `state_changes` 提交路径。

`narrative` 的结构与示例见 `app/engine/narrative_dsl.py` 和 `app/engine/demo_story.py`：

- `locations` 定义地图出口及旅行时间。
- `interactions` 定义语义标签、地点/物品/标记前置条件、消耗、检定名、成功/失败效果。
- `anchors` 按书写顺序检测时间/地点/标记/物品条件；只触发一次；可暂停并等待 `resume_flag`，也可给出结局。多个锚点同时满足时，前面的结局优先；示例将截止事件放在最前。
- `rules.checks` 复用已有白名单表达式和随机判定引擎。模型不能提交成功率、数值效果或结果。
- 动作按步骤执行，时间在每步结束时结算，随后检测锚点；中途动作失败不撤销之前已执行动作的后果。任一步计算异常或数据库提交失败则整回合回滚。

`World.progress_json.narrative` 保存版本计数、游戏时间、标记、已触发锚点、暂停和结局；`WorldPlayer.private_state` 保存位置、生命、物品数量、关系、线索、属性、经验及等级。新运行时以 `inventory` 为背包事实来源，`items` 仅为展示镜像，不经过旧实体层。每次 `PlayerAction.intent` 保存动作列表、版本及结构化回执，`outcome` 保存回执/叙述。没有增加或修改数据库列，无需表结构迁移。

意图解析期间释放数据库事务；提交前以 SQLite `BEGIN IMMEDIATE` 短写事务重新读取世界与玩家，并校验版本。过期计划需重新输入，不在改变后的世界上盲目执行。状态、动作记录和兜底回执一次提交，之后才请求叙述；叙述服务不可用时展示持久化回执。正常叙述也附世界记录，以便核对事实。

```bash
.venv/bin/python tests/web_test.py

```

新增测试涵盖规则验收、真实随机成功与失败、缺少材料、复合步骤停止、暂停、结局、重新连接存档、提交失败回滚、叙述故障回执、过期计划拒绝，以及通道入口和旧 tick 隔离。

## 后续缺口

这不是完整 v0.2 MVP。目前仍需补齐：上传小说后自动生成并验证新运行时规则、角色自定义与技能/装备玩法、NPC 独立计划和知识层、自动播放速度及偏好、存档槽/重生、更多基础动作及开放环境模拟。当前 `/upload` 仍生成旧版剧本，`/continue` 是按需推进，尚非定时自动播放。

AI 文本润色仍可能与回执出现语义偏差；本轮保证模型不能改写结构化状态，并始终显示真实回执，尚未实现叙述事实一致性自动评估。正式玩法验证还需要真实模型长会话试玩。
