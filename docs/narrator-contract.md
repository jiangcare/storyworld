这不是一个等待玩家提问并回答的 AI 聊天游戏。它是一部由游戏世界持续驱动、由 AI 实时写作、玩家可以随时介入并改变走向的可游玩小说。

1. 故事默认自己前进，而不是默认等待玩家。
2. 玩家默认自由输入，而不是默认做选择题。
3. 游戏机制默认隐藏在小说下面，而不是用系统语言打断小说。

# Narrative Stream 与玩家体验契约

## 最高产品验收约束

**首先，它是一部正在实时发生、玩家身处其中的小说；其次，它才是游戏。**

此契约优先于本仓库其他文档中的交互示例和旧实现习惯。不能用“支持聊天、剧情和选项”作为体验已经合格的依据。

默认玩家看到的是场景、动作、对白、声音、触感与细节构成的小说正文。不是聊天助手对用户的回复，也不是 RPG 控制面板。POV 保持一致，当前内置单人世界使用第二人称。玩家输入是介入世界的意图，不是世界前进的时钟。

## Narrator Contract

Narrator MUST：

- 通过场景、人物动作、对白与感官细节呈现已经发生的事实，保持人物口吻、POV 和时间顺序。
- 承接近期正文，不逐轮重新介绍世界，不先总结刚刚发生的事。
- 在玩家需要介入的场面自然停笔，不补“你准备怎么办”。
- 将引擎事件当作事实依据，不能照抄事件字段、规则回执、Prompt 或状态面板。
- 作为故事叙述者写作，正文不出现 AI Assistant、模型调用或系统处理过程。

Narrator MUST NOT：

- 默认输出选项、编号、推荐行动、教学、机制说明、数值变化、存档提示、世界记录等附录。
- 默认以系统提问结尾，包括“请选择”“接下来你想做什么”“是否进入”。NPC 在场景内真实提出的问题可以保留。
- 擅自发明已经获得的物品、成功的检定、未发现的秘密或尚未发生的事件。
- 替玩家决定信念、爱恨、效忠、背叛、杀人、重大任务、阵营、重要资源消耗或不可逆行动。

`/guide`、`/status`、`/autonomy` 等是玩家主动打开的系统界面，不适用“纯正文”限制。正常叙述不得用一行“修为 +10”或“经过60分钟”作为固定尾巴。数字可以是场景内的事实（例如门外七个人、距离天黑十九分钟），不能是状态字段泄露。

## 三种自主性分别定义

默认：World 95 / Player 30 / Narrative 85。它们不是同一个“自动播放”开关，也不是模型自由修改存档的权限。

| 参数 | 控制什么 | 不授予什么 |
| --- | --- | --- |
| World Autonomy | 可自主发生的环境与 NPC 事件范围；0 停止世界自主推进 | 不得直接修改玩家资源、关系、阵营与目标 |
| Player Autonomy | 无状态后果的姿态等低风险细节是否可以自动描述 | 任何数值都不能授予重大决策权 |
| Narrative Autonomy | 无需玩家消息时的连续叙述节奏；0 停止主动叙述 | 不得越过关键介入点 |

当前运行时以白名单世界事件为事实来源，Director 确定下一事件是否可发生及是否需要介入。不是让 LLM 任意发明状态。自动事件的结构只允许世界天气与 NPC 活动/情绪变化，没有玩家 Effect；角色的行动仍走原有验收与提交事务。

Player Autonomy 达到30允许剧本提供纯感官/姿态细节，低于30省略这些细节；本阶段不自动为玩家移动、消费或执行礼貌承诺。提高参数不能突破此边界。自定义策略和更复杂的授权行动需要后续独立的权限模型。

## 运行模型

`叙事时钟 → Director 验收事件 → 提交世界变化与正文 → 投递正文 → 下一次时钟`

玩家可随时输入。输入处理与自动事件在同一玩家的运行通道中串行，消息抵达后优先处理玩家介入。关键事件提交时即写入持久化介入标记，此后不得继续产出事件，直到玩家明确行动或主动放任事件继续。拒绝、闲聊、问状态、观察不能自动替玩家解决关键抉择。

暂停、叙事游标、世界时钟、事件事实与待投递正文必须持久化。传输失败重试已有事件，不重新运行事件；不承诺所有外部聊天服务都支持严格一次投递。退出或离线时不补刷大量旧消息；重启后从存档继续，不因真实世界离线时长让角色受到惩罚。

## UX 验收案例

1. 雨幕便利店切片在玩家不输入时，约十分钟连续输出二十段不同的世界/NPC 正文；末段才停在危险介入点。修仙地区的三段连播只是底层机制回归，不足以通过小说体验验收。
2. 进入真正介入点后，多次时钟扫描不增加时间、不修改资源、不新增事件。
3. 玩家随时移动、说出可执行意图或明确放任，世界随后继续；聊天或查看面板不等于选择。
4. 默认正文没有菜单、助手式收尾、属性加减、存档提示；主动打开系统界面才出现这些信息。
5. 提高 World 或 Narrative 数值不能自动消耗玩家灵石、提升境界、加入宗门或改变好恶。
6. 网络失败、重复扫描、进程重启不重复执行同一事件；恢复后仍停在尚未解决的介入点。
7. Web、Telegram、CLI 都能主动输出。CLI 等待输入时不能阻塞叙事时钟。

九个修仙地区先使用编写并验收的事件段落；此版本不声称具备无限生成地图、任意物理模拟或无限自由 NPC 推理。旧有限剧本没有事件流定义时仍使用原有规则，不能自动编造它们的未来剧情。

## 已实现的运行细节

- `app/engine/stream.py` 是规则化 Director 与时钟；`stream_scenes.py` 提供当前修仙世界的九地事件。世界事件由已验收作者事实驱动；自动段落和玩家动作都可通过 DeepSeek Harness 结合近期正文润色。自动段落润色最多等待8秒，失败使用作者正文，重试投递不再生成另一份文本。没有宣称实现任意 LLM NPC 自主规划。
- 标准内置修仙内容默认启用；编辑过的自定义剧本需显式提供 `narrative.stream`。事件流不能与旧版时间锚点混用，避免两个时钟各自触发同一后果。
- Narrative Autonomy 对应段落间隔 `max(8, 60 - value // 2)` 秒，默认18秒；World 按事件的最低自主性门槛决定候选范围。数值为0时停止对应自主推进。Player 只影响作者提供的无状态姿态细节，不消费物品。
- Web 只在该玩家个人连接存在时输出，CLI 只在终端运行时输出；Telegram 没有可靠在线状态，限定在最近交互后的15分钟内主动输出。进程重启后 Telegram 需玩家再次交互激活。
- 每次最多生成一个事件，未投递段落未确认前不再生成下一条。表 `narrative_beats` 单独保存事件、正文和投递状态，不伪造 `PlayerAction`。各渠道共享跨进程租约，取消输入也会释放锁。
- `/pause` 不解除介入点；`/stream on` 也不会替玩家解决介入点。玩家明确移动、交互或休息后重新推进；观察、询问、普通等待不解除，主动 `/pass` 可以表达暂不介入。
- `/resume` 重读最近正文；只有 `/status` 主动打开完整角色面板。最近正文按同一世界修订号合并玩家动作与自主事件。

验证：`python tests/stream_test.py`（包含无输入连播、CLI 非阻塞输入、真实 Web 主动推送、断线清锁、重试及主导权边界），以及 `python tests/prose_test.py`。

## Mechanics underneath, Narrative on top

库存、时间与 NPC 情绪由引擎静默提交。物品数量可以成为小说里的事实：“三瓶水和两包饼干被收入背包”，不能跟随一条“获得矿泉水×3”。玩家主动查看 `/status` 时才列库存。后台 TIME / EVENT / NPC / 属性增减不能原样投递；错误输出、正确输出、十分钟节奏和提问边界详见 [切片体验规格](novel-vertical-slice.md)。

切片固定30秒间隔、非循环；每次根据已提交 flags 选择当前事件变体，同时改变 NPC 的实际活动记录。不会因玩家换位置重新播放第一段。结束后 `/pass` 不会从头重放。修仙旧事件仍使用原有自主性间隔与循环策略。
