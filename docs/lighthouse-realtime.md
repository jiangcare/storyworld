# 孤岛灯塔：行动立即返回结果

旧版“孤岛灯塔”按每日结算运行，因此玩家问“信件内容是什么”时，只会收到“已记录行动”，结果要等下一次剧情推送。新版本 **孤岛灯塔 · 即时探索** 使用与钟楼雨夜相同的事务规则：校验、执行、保存、返回结果。

## 玩家会看到什么

- 创建后立即说明漂流瓶已捡到、信在手里，并提供读信选项。
- “漂流瓶的信写的是什么”“信件内容是什么”“信上写了什么”“读信”直接执行已定义的读信交互，不等待每日结算。
- 信件原文沿用原剧本中的线索：“你父亲不是死于意外。来灯塔地下室，那里有答案。”首次读信消耗 1 分钟、记录线索；重复询问直接重读，不重复耗时或发放经验。
- “这是哪”根据实际存档返回当前位置；“游戏规则是什么”“游戏规则时什么”以及“都说说”直接展示当前目标、玩法和可执行选项。这些问法不调用模型，也不生成未知剧情。
- 地下室、灯室、检修道和码头均有已编写的交互结果与结局。模型只润色已经发生的结果。信件这类原文内容直接返回，不需要模型润色。

任意后续对话仍使用原有的交流/意图路径；这里对“都说说”明确展示完整玩法，并未增加跨场景的无限聊天记忆。

## 已有部署如何升级

更新代码并重启服务。查看 `/scripts`、`/status`、`/resume` 或发送下一条游戏输入时，会检查旧版内置灯塔。

程序只识别**内容与旧版内置剧本完全相同、来源为 official、仍上架的“孤岛灯塔”**。创建新版入口并下架旧入口，不覆盖旧版剧本内容。作者修改过的剧本、用户上传剧本不会被自动替换。

以下条件全部满足的旧世界自动衔接：进行中、第 1 天、尚未每日结算、只有一个存活角色、没有已生成场景或已结算行动、角色仍处于干净的初始状态、没有额外世界进度。世界 ID、角色 ID 和原有行动行均保留；旧 script_id、初始角色状态和历史行动 ID 存在 `progress_json.legacy_daily` 中。

之前排队的输入只保留为历史，**不会自动重放或重复扣点**。衔接后再次发“信件内容是什么”，就会即时执行一次读信。新模式不受旧的每日行动点计数限制。

已经推进过剧情、角色状态变化过或已经结束的旧世界保持原样，继续引用原剧本。需要体验即时版本时可以新建“孤岛灯塔 · 即时探索”。其他每日剧本在记录行动时会明确说明结果何时出现。

升级采用 SQLite 短写事务；失败时新版剧本、旧入口状态和存档修改一起回滚。

## 作者可使用的交互字段

即时规则的 `Interaction` 新增三个可选字段，旧剧本无需修改：

- `aliases`：常见的完整输入短句，对符合条件的交互作确定性匹配；仍先经过输入边界校验。
- `repeat_text`：一次性交互已完成后，匹配相同短句时可重读的文本；不会再次执行效果。
- `verbatim`：单个交互完成后直接返回作者回执，跳过 AI 润色。适用于信件、碑文等必须忠实展示的内容。

验证命令：`python tests/lighthouse_test.py`。包含原对话回放、即时读信、重读、完整结局、开场升级、保留历史、版本幂等及事务回滚；测试不使用真实 API Key。
