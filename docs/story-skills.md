这是一部由世界持续驱动、玩家可以随时介入的可游玩小说。

# 第一个剧本 Skill：长生录 · 青岚山居

本版提供独立的修仙生活剧本包。由官方 DeepSeek Harness 加载 `SKILL.md`，模型读取当前世界、按需读规则、调用包内 Python，再由平台统一保存。玩家没有预设动作清单；新组合通过普通物件的属性与工具用途表达。

## 开始游玩

这台已准备兼容环境的主机：

```bash
cd /root/GoldenHub/storyworld
./run_cli_compatible.sh --story changsheng
```

正常 Linux / Python 3.11 部署：安装 `requirements-harness.txt`，配置项目 `.env`，然后：

```bash
python run_cli.py --story changsheng
```

默认使用独立的 `changsheng-skills` 档案，再次运行会恢复。同一主机另开一段旅程可加 `--profile 山居二周目`。已有 CLI、Web、Telegram 的剧本列表也会在种子初始化后出现这个剧本；不用另接一套聊天渠道。代码更新不等于已重启线上服务。

开局在雨后的山居：檐下有水盆、竹片、棉布与麻绳，庭院里有照看秧苗的阿禾，来借干燥地方的许掌柜；坊市里还有修补器具的陆砚。没有主线或终局。

直接写想做的事，例如把手边材料组合起来、和掌柜商量条件、研读旧册，或者安静看人物自己活动。`/status` 查看真实状态，`/pause` 暂停，`/stream on` 恢复，`/pass` 表达暂不介入，`/resume` 重读最近正文，`/quit` 退出。

Skills 版的自由交互与自主叙事需要真实 AI；不可用时明确报错，不将旧版预写动作伪装成 Skill。当前兼容启动脚本依赖本机已有的 `.infra` 缓存，详见 [运行环境](runtime-rules-play.md#运行环境)。

## 剧本包

```text
worlds/changsheng/
  manifest.json           包身份、版本、规则和计算脚本的登记
  SKILL.md                主持规范、自由意图、小说契约、玩家主导权
  world.json              初始人物、物件、地点、资源与可组合属性
  rules/living.md         普通生活及物件操作
  rules/cultivation.md    修行、有限功法、灵力、试法、复活
  rules/exchange.md       报价、交换、劳务商议和明确接受
  scripts/*.py           本剧本的确定性计算
```

平台位于 `app/worlds/`，不按“修炼/炼丹/水线开门”等剧本动作分支执行。普通物件的组合使用根据属性、用途标签和现有能力计算；同一种通用操作可用于不同对象。`introduce` 只取出普通余料，后续使用必须另行计算，不能把“打算用来撑门”误写成“门已经撑住”。

内置旧「凡尘修仙」保留为兼容版本，原有存档继续用原引擎。第一版没有自动迁移旧修为、动态功法和交易记录，也没有把所有历史剧本一并迁移成 Skills。新剧本包是独立版本，不能把旧存档的缺省值当成新角色重新初始化。

## 实际调用链

`玩家输入或叙事时钟 → SQLite 读取快照并固定随机票据 → Harness 官方 skill 工具 → world_context → 按需 read_rule / calculate / scene → 候选正文 → 事实核对 → SQLite 原子提交 → 投递`

- 使用已验证的官方 SDK/runtime `0.1.2rc1`。在 `sdk-minimal` 上显式接入官方 skill、skill-filesystem、tool-skill；只提供当前剧本，关闭默认的项目和个人 Skill 根目录。
- 通用终端、文件读写、编辑器和进程工具保持关闭。`calculate` 经本次请求独有的回环桥接执行登记的 Python，模型不能提交路径、代码、环境变量、世界 ID 或自造玩家状态。
- Python 子进程仅获得状态快照、参数和固定随机值，使用隔离启动、清空凭据环境、执行超时与资源上限。只允许维护者安装的可信脚本；这个运行器不是任意恶意 Python 的安全沙箱。玩家和模型没有安装或改写剧本脚本的工具。
- 每次主持最多14次模型请求、24次世界工具调用、6次计算。重复同参计算返回本回合已有结果，不再执行。实际计算成功才更新候选状态；交易同时核对双方库存。
- 模型事实核对检查候选正文和场景是否与位置、物件、资源、时间、能力或授权冲突。格式或事实检查失败最多从原快照重做一次，使用同一随机票据。仍失败就不保存、不投递；核对不是数学证明，细微语义仍需试玩评估。

## 保存与自主推进

剧本内容按 ID、版本及全部规则/脚本文件哈希绑定。存档与安装文件不一致时停止执行，不静默热替换规则。正式发布后的包应保持不可变，升级需保留旧包或提供经过验证的迁移；当前没有自动迁移工具。

人物、物件属性、报价和近期目击记忆进入 SQLite。角色状态独立保存；一次行动的后果、正文和审计记录同一事务提交。当前保留80条活跃记忆，报价保留独立结构化状态；旧段落与工具记录在行动/事件表中保留，尚未提供无限历史的自动语义检索。人物目击范围按剧本定义的可感知区域判断，不是完整视线或声学模拟。

`skill_turn_tickets` 在同一世界修订号固定随机票据。网络等待不占写锁，提交时重新核对完整世界、玩家、剧本快照，防止覆盖新事实。稳定消息 ID 重放已提交正文，不重复扣费；没有稳定 ID 的另一次输入仍视为新输入。

世界默认约45秒发起一段自主创作，生成过程另需模型时间。没有预写的未来事件表；NPC 按当前情况说话和活动。自主模式的计算工具不可用，不能改变玩家资源、位置、成长或承诺。需要玩家决定时持久暂停。未投递正文先重试投递，不重新生成；离线不追补惩罚。玩家输入抵达时取消尚未提交的自主候选，优先处理输入。

## 当前边界

可试玩：少量相连地点、普通物件组合、NPC 对话与记忆、实物报价与交换、劳务条件商议、旧册功法参数补全、修炼与蓄灵、有限水灵操控、突破与无限复苏、受控试法。

劳务目前可提出并记住条件，不能谎称已经完成服务、获得炉子使用权或发放报酬。任意超能力、完整 NPC 战斗、远方无限地图、复杂加工产业和规则脚本自动生成仍未实现。物件的新用法依赖已有属性构件，超出构件时需要补充剧本规则；不是无限物理模拟。

```bash
python tests/world_skills_test.py

STORYWORLD_TEST_HARNESS_RUNTIME=1 python tests/world_harness_test.py

```

SQLite 与实际 Python 计算测试覆盖组合行动、重启记忆、交易守恒、同消息和同工具重放、并发、撤销、回滚、隔离、自动叙事暂停、输入抢占、正文与事实核对。真实运行时夹具另验证模型确实加载了官方 Skill、调用了计算工具，且没有暴露终端或文件工具。

真实试玩记录与本轮发现的问题见 [Skills 试玩记录](story-skills-playtest.md)。真人长时间游玩仍需继续收集反馈，不能用机器断言替代是否愿意读下去的评价。
