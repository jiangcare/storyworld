# 阅读节奏与世界自主性

2026-09-11。世界可以自己发展，玩家决定何时阅读下一段。此规格替代此前“默认固定间隔连续输出”的交互要求；世界、玩家和叙事三种自主性仍各自保留。

## 默认逐段阅读

开局与每次交互结束后停住。Web 输入框上方提供“继续阅读”按钮，CLI / Telegram 使用 `/read`。它只请求一个世界片段，不新增玩家行动，不替玩家答应 NPC、使用物品或解除关键抉择。玩家也可以随时直接写出自己的行动。

许可记录在当前世界的 `progress_json.stream`，成功提交一段即消耗。基于同一修订号的重复点击不会排队生成多个片段；旧修订号的请求不执行。需要介入、事件已结束或自主性关闭时给出明确反馈。失败不改变故事事实，等待重试；玩家行动提交后取消尚未消费的阅读许可。

已有存档缺少 `reading_mode` 时按阅读模式处理，不自动沿用旧版的连续推送。此改变属于平台阅读设置，不修改 Skills 包哈希，不重置修为、人物记忆、时钟或介入点。

## 可选连续阅读

Web 勾选“连续阅读”，其他渠道使用 `/stream on`。取消勾选或 `/pause` 停止连续输出；之后仍可主动续读一段。设置按世界保存。

网页满足以下条件才允许自动推进：

- 页面可见，输入框没有草稿，当前内容已滚动到底；读到底后再停顿至少12秒。
- 90秒内有点击、按键、滚轮或触摸活动；长期闲置的前台页也停止输出，点击正文后重新等待阅读停顿。程序自动滚动不算人在阅读。
- 当前连接报告的世界修订号一致，阅读状态心跳不超过15秒。打开另一个标签页不会让后台连接获得阅读许可。

切到后台、开始输入、向上翻阅或连接断开，取消尚未提交的 Skills 自主候选；生成结束提交前再核对阅读状态。新段落不把正在回看的玩家强行拉到最底部。重新连接补取历史，以持久消息 ID 去重。

这些条件只衡量浏览器活动，不能判断玩家是否真的读懂或想好了；因此连续阅读需要主动开启，默认模式不依赖阅读速度或心跳猜测。CLI / Telegram 无法测量滚动与页面可见性，连续模式沿用各渠道在线/近期活动限制；默认 `/read` 一段一段阅读。

已提交而未投递的段落会保留，重连后重试原文，不重新计算。离线的现实时间不会补成世界事件或角色惩罚。关键介入点仍需要玩家明确回应；“继续阅读”不会自动执行 `/pass`。

## 验证

`tests/world_skills_test.py`：真实 SQLite 下验证默认与旧存档不自动推进、一次许可一段、固定修订号去重、重启、玩家主导权，以及离开阅读状态后候选不提交。

`tests/stream_test.py`：真实 WebSocket 按钮协议、逐段阅读、连续阅读、关键介入暂停、断线和事件投递回归；原连续叙事样例显式开启连续模式。

`node tests/web_reading_test.js`：执行网页实际脚本，使用 DOM、时钟和连接夹具验证可见性、输入、滚动、停顿、闲置、双击及历史去重。此自动测试不代替真人浏览器阅读体验。
